# 隔离边界与复用审计

基线：`d89f8657062ac2bd3f5675a20e661d52acbba7b6`。所有受跟踪的原文件保持逐字节一致。

| 文件 | 职责 |
|---|---|
| `server/app.py` | 一个房间、身份/重连、输入期限、固定步长、最新帧广播、HTTP/WebSocket安全 |
| `server/__main__.py` | 独立端口与显式 HTTP/TLS 启动，不终止已有进程 |
| `shared/protocol.py` | 版本、消息形状、有限数值、输入序号等校验 |
| `adapters/core_adapter.py` | 仅双人规则接口，复用 `Game.update` 一次/帧、刷怪、武器、技能、原 Boss AI |
| `adapters/snapshot.py` | 明确视觉字段白名单、单调实体编号/引用、JSON，无 pickle/eval/内存地址 |
| `adapters/presentation.py` | 原 Game/entity.draw 只读展示，恢复图片/字体，不执行战斗更新 |
| `client/main.py` | Pygbag异步展示循环与 JS 桥接 |
| `web/` | 原生同源 WebSocket、连接/大厅/商店/键盘/触屏 DOM UI |
| `tools/build_web.py` | 复用原构建纯步骤，但重定向所有输出/缓存到 online 下 |

## 原核心保留内容

`game_core/config.py` 的武器/角色/敌人/关卡/难度定义，`Game._update_playing`、`_update_boss_fight` 的完整战斗流程，所有实体/技能行为、动画、素材加载、BossSignature、声音与音乐生成器均保持原文件不动。服务器复用原核心全部九个普通关卡及过渡，结束于原普通战役终点；不接入无限模式。原 PC/Web 入口不导入 online，因此其功能和依赖不因本次增加而改变。

适配方法：输入由网络注入，原单机轮询接口在子类禁用；健康、命中、生命、装备、购物、结束规则用局部覆写；不复制两段完整战斗循环。原单人引用中的共享金币通过共享钱包适配，健康技能用受控玩家上下文。六类原 Boss 签名技能的世界效果仍只更新一次，但命中记录按玩家分开；牛、宗宗、八岐等特殊攻击分别处理两名活着的目标。回旋斧用在线专用子类保存每名玩家的命中冷却，不修改原实体。被动治疗与明确技能施法者上下文分开，避免默认 P1 引用吞掉 P2 的治疗。

`game_core.game` 与 `game_core.orochi` 的声音绑定只在服务器单次同步 step/action 中临时捕获并在 finally 恢复，转换成带单调编号事件，由客户端去重播放；不存在跨 await 的替换。原单机路径没有这些操作。

## 生命周期

- 连接初始必须 hello(版本/房间码/可选令牌)，服务器决定席位。
- 两位都已准备后，P1 才能 start；新 match_id 隔离旧输入/旧渲染对象。
- input 和一次性 action 使用每连接单调 seq；输入超400ms过期清零。
- 断线/隐藏暂停整个世界，重新连接/回前台后恢复。只有一份权威状态，没有房主迁移。
- 商店是双方关闭确认，不是任意一个关闭就恢复。
- 异常时记录服务端日志、清空输入、暂停并发送 server_error，不继续静默计算。

## 状态同步

白名单列出每一种可视实体及字段，包括原动画时钟、Boss攻击姿态、技能owner、弹幕与预警。图片、Surface、Font、任意 Python属性不会被发送。稳定编号不是 `id(object)`，旧对象消失后客户端回收。客户端收到新对局会重建缓存。服务端不接受客户端视觉状态，伤害、金币、资源没有网络写入口。

性能采样包含 JSON序列化但不代表手机帧率或真实网络延迟。当前采取完整快照、20Hz视觉状态、60Hz绘制，无预测/插值。客户端/真机验证是后续验收关卡，不能靠 Python 模拟或构建成功替代。

## 九关特殊视觉

快照明确列出六类签名技能、牛 Boss 护盾/冲撞/雷电与回旋斧、宗宗融合/分身/复活/雪、八岐蛇头/分身/吐息/激光/风暴/死亡特效字段。客户端按原类型重建视觉实体、保留资源缓存，使用原实体绘制函数。测试把服务端原对象绘制与 JSON 往返后的客户端绘制进行逐像素比较。不同关卡背景、过渡淡入淡出及普通/Boss音乐跟随权威状态。
