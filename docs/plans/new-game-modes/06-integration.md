## 实施一包时怎样交接

| 阶段 | 建议改动范围 | 可以交给下一包的证据 |
| --- | --- | --- |
| F0 | `game_core/main.py`、`game_core/menu_ui.py`、单机菜单动作、`game_core/modes/`、主网页打包 | 从首页进入第一个真实单人模式，暂停、换方向、退出，立即开原战役。提供可重放的一段输入 |
| F1 | `online/shared/protocol.py`、`online/server/{host,app}.py`、原生／网页传输、`online/client/integrated.py`、新模式房间适配 | 原生和网页两席能共同开始、重连、结束、再开始。旧客户端能与新客户端开原战役 |
| 每个 M 包 | 该模式规则、数据、输入、呈现、必要美术与专属用例 | 能正常玩完形式各异的全部幕、海域、订单、赛道或回合。给出首版内容清单，以及第一次试玩时最难读懂的一处机制和调整结果 |
| P | `phaser/src/main.js`、`scene.js`、`touch-layout.js`、单人新模式 JS、构建脚本与共享内容 | 三项从独立网页实际开局。有相同地图、输入和结算的 Python／JS 对照。两种联机专属入口能打开统一主网页 |
| I | 主入口、主网页离线构建、跨模式切换、房间回收、回归 | 从玩家入口走完验收矩阵，保留命令和代表性截图／结果。说明测过的设备与未复现的现场条件 |

多人协作时可分别拥有各自模式目录和内容文件。公共菜单、协议、Web 构建和原生传输共用一套接口，安排一个改动批次集中合入。模式包提交自己的目录条目和输入白名单。单个 agent 顺序实施也可按同一边界推进。初值可据试玩调整。变更动作意义、胜负规则、支持人数或平台时先对照总任务书。

## 主网页构建与离线

1. 修改 [Web 构建器](../../../web/run_web.py) 的 `SOURCE_FILES / source_manifest / prepare_sources`。递归枚举实际的 Python 子包与模式 JSON，保留相对目录和各包 `__init__.py`。主网页需要新联机客户端适配模块时一并加入 `LAN_WEB_PYTHON` 的实际 staging。只复制浏览器执行所需模块。
2. 当前图片以 `assets/images` 递归处理，主 Web 会跳过文件名以 `ui_` 开头的部分图片。模式命名应与实际资源加载一致，核对生成包内容，避免 PC 首页有卡图而网页空白。变更一份嵌套地图与一张卡图后，普通增量构建应识别这两项并产生新版本。
3. 运行一次主网页真实构建，检查打包内容有 Python 入口、三种单人地图、所有模式图、局域网输入桥。浏览器等「离线资源已保存」后断网并冷启动原地址，实际进入三个单人模式各完成一项可观察动作。恢复网络后仍可加入房间。离线状态能浏览双人卡，按钮说明联机需要连接宿主。
4. 资源按当前模式和幕加载，进入首页只预览卡面。PC 2K／4K、主网页画质切换后只替换显示资源。复用持续资源缓存，清理离开模式后的临时 Surface、音频循环、触控捕获、快照历史和航迹播放指针。

## 独立 Phaser 的交付办法

- [网页入口](../../../phaser/src/main.js) 当前管理菜单及 `new Battle(...)`，[场景](../../../phaser/src/scene.js) 负责 Phaser 绘制。为三个单人模式建立单独的模拟／呈现分派，在当前页面处理暂停、离开与触控清理。`battle.js` 中的战役弹幕和武器逻辑继续服务原入口。
- [构建器](../../../phaser/tools/build.py) 已输出 `campaign.json / assets.json / offline.json`。把 `assets/modes/` 的共享内容按同样稳定 ID 打入 `dist/modes/`，在离线清单生成前完成复制。三种单人规则读取相同的单位、表和碰撞数据。JSON 编码 UTF-8。涉及随机摆位时，先用两端都实现的固定规则选摆位（例如 `variant = unsigned_seed % variant_count`），再读取完整预制表。
- 三组跨端输入样例分别记录起点、地图版本、动作发生 tick、最终状态。移动物理允许模式文档给定的像素／tick 误差，签收清单、所走分支、计时门次序、胜负、金币／收入等离散结果应一致。主网页与原生共用 Python，无需维护两份游戏数值。
- 新增构建选项 `--main-game-url`（默认未配置）。发布时可设为实际可访问的主网页地址。独立页对双人按钮拼接 `mode=run_gun/sub_courier/tide_race/boss_duel` 中的实际单个 ID，主网页识别后定位对应卡，玩家再选择建房／加入。如果链接本身有 `room`，优先原邀请／重连流程，模式以房间为准。未配置或离线时，显示「请在主网页版或 PC 版创建／加入房间」。地址使用部署者配置的 HTTP(S) 源，测试包含部署于子目录的情况。
- Phaser 单人记录保存在该客户端自己的本地库。真实浏览器中验证安装离线缓存、关闭标签页后重开，以及新版本缓存替换。联机跳转以能在主页面实际建房或加入作为完成证据。

## 运行时与数据对照样例

房间设置的三个例子如下。`mode_options` 是拟新增字段。线上只接受已经实现且协商支持的玩法，完整校验见[公共约定](00-shared-runtime.md)。

```json
[
  {"type":"room_settings","mode":"run_gun","orientation":"landscape","mode_options":{"stage":"harbor","run_type":"story"}},
  {"type":"room_settings","mode":"sub_courier","orientation":"portrait","mode_options":{"order":"calf"}},
  {"type":"room_settings","mode":"boss_duel","orientation":"landscape","mode_options":{"boss":"whale"}}
]
```

| 对照输入 | 建议的断言 |
| --- | --- |
| 横版在静止平地站定，按跳并在第 4 tick 松开，再从同一点完整长按 | 短跳最高点低于长跳。落在同一平台。加入移动平台和朝向变化后两端坐标差符合 S8 |
| 寻宝同一物品先卸下再装、签收两次，另一次浮袋签收后立刻弃艇 | 前者一个实例只进账一次。后者保留已签收这件。刷新应用仍能看到图鉴 |
| 潜艇两席同 tick 确认换岗，随后送入上一代的压载动作 | 岗位只互换一次，压载保持不变，恢复输入后新轮机员可以改变它 |
| 竞速同 tick 两鱼从同侧跨过终点，再把第二条样例改为跳过中间门 | 第一条并列。第二条绕过终点仍未完赛，不能产生最佳航迹 |
| Boss 同 tick 双方归零，换边后收到上一回合的延迟施放 | 本轮记击倒首领、英雄 0 HP。第二回合恢复规定的初始资源，旧施放不出现 |

定向回归优先放入与行为最近的现有测试目录。新增用例是为了捕捉上表和每份文档中现有测试没有覆盖的风险。可用固定 tick 快速验证临界帧，同时保留从真实菜单游玩的路径。测试样例中的人工放置对象只证明该条规则。

## 整体验收矩阵

| 编号 | 入口与场景 | 客观结果 |
| --- | --- | --- |
| I1 模式发现 | 原生和主 Web 从统一首页打开玩法大厅。分别用键盘、点击和触摸选七张卡 | 战役、无限和五项新玩法可辨。人数、目标、按钮与真实支持一致。原菜单快捷键、F11 和返回可用 |
| I2 单人三项 | 各跑横版三幕、寻宝三图、竞速三轨。结算后依次切换横版 → 寻宝 → 竞速 → 无限 | 前一局的重力、氧气、射击、时钟、镜头与按钮均不会影响后一局，成绩写到相应模式 |
| I3 双人四项 | 同一对设备分别从横版、快递、竞速、Boss 四张卡建房，再从「创建房间」直接进入选择 | 房主选项同步到两席，重选后准备失效。两端从各自输入能达成该模式目标 |
| I4 断线与退场 | 短断线、切后台、旋转不匹配、主动退出及断线超时。覆盖快递险情、竞速冲线前与冲线后、Boss 换边时 | 仍需操作的席位暂断会冻结时间。竞速观赛者离线时另一人仍能跑到截止。主动退场／超时按各模式处理，留下者看得到真实结果并能继续操作 |
| I5 结果投递 | 在结算附近丢弃中间快照，刷新一端，快速点再来一局，试一次主动离席 | 最后结果可从完整快照恢复。房间保留最终结果供重连读取，完整两席能再赛或回大厅，均已离开才回收。下一局新 ID 不接收上一局动作 |
| I6 屏幕与性能 | 桌面 2K／4K、手机横／竖布局。忙碌场面连续采样至少 30 秒，观察录像和帧时间 | 坐标、碰撞和触摸映射一致。无输入时模拟和相机稳定。记录设备、分辨率、有效 tick、帧间隔中位数／P95，与同设备现有玩法对照。持续卡顿要定位到真实场景 |
| I7 离线与存储 | 两种网页各自先缓存、再断网冷启。新建浏览器标签重复提交旧结果 | 三单人入口仍可玩，已签收和最佳航迹正确。快递／Boss 提示需要宿主。存储不可用仍能给出本局结果 |
| I8 版本与旧入口 | 基线统一客户端＋新客户端开原战役／无限。旧 v1 预览用自身入口。新客户端连旧宿主 | 旧客户端不会误入新界面。原战役的商店、复活及无限的继续／退出仍按现有流程工作 |
| I9 独立 Phaser | 用配置与未配置主网页地址的两个构建，验证三项原生 JS 单人、双人跳转、房间邀请优先 | 单人能断网冷开，已配置站点能到实际主网页对应卡。未配置时可读到操作说明 |
| I10 实际设备 | 原生 PC＋手机主网页，交换房主。两部手机连同一宿主。可用时再做双原生 PC | 记录键鼠／多指、耳目反馈、预警可见性、视口切换、岗位对调和网络恢复。模拟器结果在记录中单列 |

对主动离席的终态要专门检查 `Host.remove` 与 `Room.pause_reason`。快递中止、竞速未过线者弃赛、Boss 弃权均须给剩余席位发出可重建的最终状态。单方留在终态时允许其查看后退出，完整两席可再赛或回大厅。横版同伴离席后可独自继续，竞速已过线者离开后另一人可独自跑完剩余时间。这两条路径都要在只剩一个操作席位时推进时钟。回收路径还要覆盖两人相继退出、都掉线以及在结果页又有人刷新。

## 2026-11-26 方案测试记录

基线 `ac578c0`。仓库当时有五份设计，五个模式的运行代码和正式地图尚待实现。本轮将文档中的初值代入独立的 60 Hz Python 参考模型，用内存 SQLite 验证签收去重。下表给出同一输入下的复验值，开发时可直接作为第一组回归样例。

| 模式 | 输入与发现 | 写回规则后的复验 |
| --- | --- | --- |
| 横版突围 | 满速 245，脚底中心在边缘前 8 px 起跳，落台比起点高 85 px。净宽 145 px 时，第 33 步下降穿过台面，人物前缘还差 4.25 px | 高台净宽改为 120 px。分别从边前 8／16 px 起跳，第 33 步分别搭上 20.75／12.75 px。同高、55 px、85 px 三档与两种起跳点的六个组合均留出至少 8 px |
| 深潜寻宝 | 浮袋寄出价值 180 的晶簇、货舱为空。原文的「空舱零收入」和已签收回执发生冲突 | 空舱无回执为 0，空舱已有晶簇回执为 180，重复签收仍为 180。浮袋预计第 300 步到船，第 299 步缺氧为 0，第 300 步同时缺氧则保住 180。初始 120 加一次补气 20，水下最长为 140 个有效秒 |
| 潜艇快递 | 用横向顺流 70 px/s 的假设泊位检验地图约束。全速倒车抵消 50 后仍以 20 px/s 漂移，无法达到低于 15 的交货条件 | 将泊位和最后 200 px 设为静水。13,200 px 合成急件航段中，前 4,000 px 有逆流 18，艇从起点静止强推出发，x=13,000 切慢靠，在 [13,200,13,240] 的中心坐标区停稳。第 5,820 步交货，耗时 97 秒。另测最后一 tick 签收成功、速度恰为 15 清零、船体归零优先失败 |
| 潮汐竞速 | P1 第 6,000 步过线、第 6,001 步离开，原文的离席规则可能推翻完赛结果。原 R2 还要求以最低目标速度 145 px/s 的飞鱼主动倒游 | 锁定完赛步，观赛者离开后比赛继续。P2 在第 7,200 步过线仍算完赛，7,201 则超时。含同 tick 并列、过线前弃赛和整局截止步的五条时间线均通过。重复计时门改用碰撞复位回到门前进行验证 |
| 今天我当 Boss | 巨鲸选最右侧安全口，英雄在 x=18，第一排 72 步后生效。原位置需要横移 682 px，即刻步行也只能走 252 px | 用英雄起点与首领选点各五个位置交叉检查。预留 12 步反应时间后，原放置法 11／25 组可达，修正规则 25／25 组可达，均可保留 4 px 余量。另验五组比分样例，覆盖双击倒计时、同帧互相击倒和完全平局 |

竞速还跑了一段可复用的教学输入。合成浪段长 1,200 px，振幅 24、波长 300、浪速 50，起点在波峰，始终向前加速。在第 1、109、206 步起跳，每次起跳 12 步后开始收翅。第 44、152、250 步依次接成一、二、三连浪，第 311 步过线。同一起点只向前巡航在第 339 步过线。两个结果可用于对照输入、浪面与碰撞是否一致。

现有代码另跑了八项定向回归，均通过。原生键盘三项、网页版战役／无限菜单一项、统一首页按钮一项、房间方向三项。直接调用现有 v2 `decode`，战役和无限设置通过，四个拟联网新模式的 ID 均返回 `invalid_settings`，与当前实施阶段一致。正式地图、真实双人通信下的这些新规则、画面和手机操作仍需在对应模式实现后实玩验收。

## 给下一位 agent 的交付回执

每完成一包，在实际交付说明中填写以下五项，后续 agent 可以直接从可复现的状态继续。

1. **可玩内容**。模式、内容 ID、人数、实际支持的 PC／主 Web／Phaser 入口与构建标识。
2. **一条复现路径**。从首页开始，列出选择、输入、观察点与到达结果的办法。带 seed 或赛道版本时写明其值。
3. **证据**。本包验收编号、测试命令与结果。给出代表性双端／单人界面、结算数据和测量设备。
4. **设计偏差**。记录经过试玩调整的数值、原因和更新位置。若某项仅完成了样段或离线模拟，标明实际范围。
5. **接续条件**。列出已经可复用的公共模块、尚未实测的设备或未完成的编号。若要回退某个有问题的模式，可先撤回它的目录注册和房间能力声明，并保留已有玩家记录。
